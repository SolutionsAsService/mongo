Join with $lookup

Inner, left and right joins, built from $lookup and $unwind.

$lookup + $unwind (inner join)

6 documents

Attach each user's orders, then split one document per order. Users with no orders disappear.

db.users.aggregate([
  { $lookup: { from: "orders", localField: "_id", foreignField: "user_id", as: "o" } },
  { $unwind: "$o" },
  { $project: { _id: 0, first_name: 1, last_name: 1, order_id: "$o._id" } }
])

Result: 6 documents

result documents

  1. { first_name: "Ana", last_name: "Silva", order_id: 101 }both
  2. { first_name: "Ana", last_name: "Silva", order_id: 102 }both
  3. { first_name: "Li", last_name: "Wei", order_id: 103 }both
  4. { first_name: "Mira", last_name: "Novak", order_id: 104 }both
  5. { first_name: "Mira", last_name: "Novak", order_id: 105 }both
  6. { first_name: "Priya", last_name: "Nair", order_id: 106 }both

In SQL

SELECT users.first_name, users.last_name, orders.order_id FROM users INNER JOIN orders ON users.user_id = orders.user_id;

The SQL gives the same answer: the build runs both on the same data and stops if they differ.

Reading it

  • $lookup adds an array o of matching orders to each user, empty if none.
  • $unwind: "$o" emits one document per array element and drops empty arrays, which is what makes this an inner join.

$lookup + $unwind, preserved (left join)

9 documents

The same pipeline, but users with no orders are kept.

db.users.aggregate([
  { $lookup: { from: "orders", localField: "_id", foreignField: "user_id", as: "o" } },
  { $unwind: { path: "$o", preserveNullAndEmptyArrays: true } },
  { $project: { _id: 0, first_name: 1, last_name: 1, order_id: "$o._id" } }
])

Result: 9 documents

result documents

  2. { first_name: "Ana", last_name: "Silva", order_id: 102 }both

  6. { first_name: "Mira", last_name: "Novak", order_id: 105 }both
  7. { first_name: "Tom", last_name: "Ellis" }no order: field absent
  8. { first_name: "Priya", last_name: "Nair", order_id: 106 }both
  9. { first_name: "Sven", last_name: "Berg" }no order: field absent

In SQL

SELECT users.first_name, users.last_name, orders.order_id FROM users LEFT JOIN orders ON users.user_id = orders.user_id;

The SQL gives the same answer: the build runs both on the same data and stops if they differ.

Reading it

  • preserveNullAndEmptyArrays: true keeps a user whose array is empty.
  • There is no NULL: where the user has no order, the order_id field is simply absent from the document.

$lookup from the other side (right join)

7 documents

MongoDB has no RIGHT JOIN. Run the left join from the orders collection instead.

db.orders.aggregate([
  { $lookup: { from: "users", localField: "user_id", foreignField: "_id", as: "u" } },
  { $unwind: { path: "$u", preserveNullAndEmptyArrays: true } },
  { $project: { _id: 0, first_name: "$u.first_name", last_name: "$u.last_name", order_id: "$_id" } }
])

Result: 7 documents

result documents

  1. { first_name: "Ana", last_name: "Silva", order_id: 101 }both
  2. { first_name: "Ana", last_name: "Silva", order_id: 102 }both
  3. { first_name: "Li", last_name: "Wei", order_id: 103 }both
  4. { first_name: "Mira", last_name: "Novak", order_id: 104 }both
  5. { first_name: "Mira", last_name: "Novak", order_id: 105 }both
  6. { first_name: "Priya", last_name: "Nair", order_id: 106 }both
  7. { order_id: 107 }no user: fields absent

In SQL

SELECT users.first_name, users.last_name, orders.order_id FROM users RIGHT JOIN orders ON users.user_id = orders.user_id;

The SQL gives the same answer: the build runs both on the same data and stops if they differ.

Reading it

  • Starting from orders and preserving unmatched ones is a right join of users and orders.
  • Order 107 points at user 99, who does not exist, so its document has no name fields.
