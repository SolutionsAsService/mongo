Find and change documents

find, insertOne, updateOne and deleteMany. The last three run in order on one collection.

Documents are JSON-like objects in a collection; no schema is declared first. Insert, update and delete run in order on one copy of users; rows are marked new, changed or removed.

find

2 documents

Read documents. The first argument is the filter, the second picks which fields come back.

db.users.find(
  { age: { $gte: 30 } },
  { _id: 0, first_name: 1, last_name: 1, age: 1 }
)

Result: 2 documents

result documents

  1. { first_name: "Omar", last_name: "Haddad", age: 42 }
  2. { first_name: "Priya", last_name: "Nair", age: 34 }

In SQL

SELECT first_name, last_name, age FROM users WHERE age >= 30;

The SQL gives the same answer: the build runs both on the same data and stops if they differ.

Reading it

  • { age: { $gte: 30 } } keeps documents whose age is 30 or more.
  • { _id: 0, first_name: 1, ... } is a projection: 1 includes a field, _id: 0 drops the default _id.
